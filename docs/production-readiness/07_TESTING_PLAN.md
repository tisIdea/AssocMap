## Existing test-source assessment

There are 39 declared PHP test methods across seven test classes (including two scaffold examples); data-provider case counts/coverage percentages are not measured. TestCase is a base class, not an additional test result. phpunit.xml uses testing mode, SQLite memory, empty DB_URL, array cache/mail/session and synchronous queue. GisScopedReadsTest and InvitationActivationServiceTest explicitly set isolated SQLite connections and prohibit stray HTTP. ## Execution stages

1. Technical checks: platform, PHP/JS syntax, Blade compile, routes, Vite and dependency advisory reports.
2. Existing isolated tests, then approved focused regression tests for consequential patches.
3. PostgreSQL/PostGIS/schema/privilege and sandbox provider integration.
4. Alpha/system tests across all implemented roles and failure states.
5. Performance/accessibility/device checks against approved thresholds.
6. User Acceptance Testing and backup restore; retain sign-off and unresolved scope exclusions.

Use [manual commands](06_DEPLOYMENT_READINESS.md). Database/provider exercises require approved nonproduction identities/fixtures and responsible-owner authorization. Do not use production records or disable constraints to make a test pass. Record missing implementation as a gap, not a successful test or a fabricated result.

## Evidence handling and acceptance rules

- Every result needs date, executor, environment, source identity, role, relevant dataset condition, actual HTTP/DB/UI outcome, artifact location and issue reference. Do not fabricate revision IDs; the user may collect a revision identity through their own approved tools.
- Remove bearer/refresh/capability tokens, passwords, cookies, emails, contact/birth records and private addresses from shared screenshots, command output, HARs, exports and logs. Prefer field names/status/geometry type instead of sensitive payloads.
- Actual Result remains blank until personally observed. Status may become Passed/Failed/Blocked/Not Applicable only with evidence and stated scope. Not implemented is a product gap, not proof a requirement passed.
- Unit/functional/Alpha/performance/acceptance sections in the manuscript must cite actual artifacts and methods. Do not infer UAT success from source or a build.
