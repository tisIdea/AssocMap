**4. Batch 2 — contextual export integration assessment (read-only)**

The existing path is `ReportRequest` → `ReportController` → `ReportService` → `ReportScope` / `ReportDataset` → `PythonReportEngine` → versioned Python contracts and canonical analytics → PDF/XLSX renderer → scope recheck before release. Laravel resolves identities and association scope; Python receives bounded authorized facts, without database or identity credentials. Screen, PDF, and XLSX use the same canonical calculations. The exporters currently render metadata, indicators, notes, and tables; new graphical PDF/XLSX charts are not established by the current exporters.

Existing types, exactly as catalogued: `comprehensive` (Comprehensive Report), `associations` (Association Distribution), `members` (Member Summary), `projects` (Project Portfolio), `trainings` (Training Participation), `production` (Production Performance), `income` (Gross Income), `activities` (Activities and Monitoring).

Scope definitions used in both matrices:

- **A:** eligible Administrator; authorized associations including archived associations. Program-wide activities with no association link appear only without municipality/association filters.
- **F:** eligible Field Officer; currently assigned, active, unarchived associations. Retained archived child records can still appear within that association scope.
- **C:** eligible Association Account; its unique current active association link and active, unarchived association. **Preview only: no PDF/XLSX export.** `ReportScope::actor(..., true)` enforces the denial before extraction/Python, and scope is rechecked before release.
- **G:** `municipality_id`, `association_id`.
- **P:** G + `program_year`, `component_id`, `project_id`.
- **E:** P + `year`, `quarter`.
- **O:** E + `month`, `product_id`.

These are reporting filter names, not arbitrary module queries. IDs use the existing UUID/integer validation. `year` is the reporting/event year and defaults to the current Manila year for types that support it; `program_year` is the administrative cohort. Month must belong to the selected quarter. Reports do not accept `status`, `archived`, free-text search, sorting, pagination, `member_id`, `training_id`, `activity_id`, `monitoring_record_id`, `barangay_id`, `area_id`, `site_validated`, or visit-report IDs. Unsupported fields are rejected, not silently applied.

“Allowed” below describes existing server permission and data coverage. It does not mean a contextual export button was implemented in this batch.
