## Scope clarifications since earlier inventory

- **F-005:** decision serialization is now source-addressed; no functional result exists. The source change was made in the separately approved preceding task.
- **Specific Area:** routes and AreaService expose create, and active areas are reference choices. The normal Area directory is assembled from Municipality/Barangay rows. Earlier wording that implied full Specific Area read/edit/deactivate management was too broad; no such update/deactivate route exists in current source.
- **City:** stored locality_type=city is displayed as City; creating a City is not an exposed type/input in the current add-area workflow. This is a scope limitation needing approved requirements, not proof every stored City is wrong.
- **GIS:** project-only mapping supersedes earlier Association Point requirements in current implementation; legacy SQL values are preserved. Formal research reconciliation is still required.
- **Account versus Member:** Association Account is an organizational login/link, not necessarily an individual official member. No role capabilities are inferred from generic catalogue fields.
- **API:** Supabase bearer /v1/me and Sanctum /user are separate contracts; installing Sanctum does not implement the mobile system.

The role matrix in the earlier [production-readiness module report](../production-readiness/02_MODULE_INVENTORY.md) is useful context, but use the exact current predicates above. Current assignment does not imply every history read has the same active-parent eligibility as GIS.
